## Patch sets

The engine is app-agnostic — it understands patch operation *types*, never a
specific bundle id or byte pattern. Any app-specific patch set (the YAML
definition plus, optionally, a hook dylib) lives entirely outside this repo,
under a `patches/<app>/` directory you provide yourself; ipa-forge ships no
patch definitions or reverse-engineered specifics for any third-party app.
See [`adding-an-app`](/docs/adding-an-app) for the shape a patch set follows.

## The reading order for a new project

1. **[`adding-an-app`](/docs/adding-an-app)** — if the task is "here's an IPA, port everything".
2. **[`adding-a-feature`](/docs/adding-a-feature)** — if the task is "add X to an existing mod".
3. [`patch-reference`](/docs/patch-reference) + [`usage`](/docs/usage) — for the exact YAML/CLI surface.
4. [`troubleshooting`](/docs/troubleshooting) — when something breaks.
